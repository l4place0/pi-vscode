# 文档工程

本目录保存项目的长期设计资料和中大型变更档案。

## 变更档案规则

每次中大型变更开始前，在 `history/` 下创建一个目录：

```text
YYYY-MM-DD-short-english-slug/
```

日期使用变更启动日期；目录创建后不因完成日期变化而重命名。每个档案从规划阶段开始存在，并通过状态表达生命周期：

- `planned`：已形成方案，尚未实施。
- `in-progress`：正在实施。
- `completed`：已经完成并通过验收。
- `abandoned`：停止实施，但保留原因和已有结论。

大型变更建议包含：

- `README.md`：状态、目标、范围和文档索引。
- `audit.md`：实施前确认的代码事实和风险。
- `plan.md`：设计、实施顺序和提交边界。
- `acceptance.md`：自动化及手工验收标准。
- `result.md`：实际修改、提交、验证结果、遗留问题和回滚说明。

规模较小但仍需要独立记录的变更可以只使用一个 `README.md`。普通小型修复直接通过 commit 和相关代码测试记录，不强制建立档案。

## 维护原则

- 档案描述已经确认的事实、决定和验证结果，不记录无价值的逐步操作日志。
- 计划变化时直接更新对应文档，并在 `result.md` 中说明最终实现与原计划的差异。
- 完成后的档案原则上只做事实纠正，不重写当时的设计背景。
- 实现代码、README、CI 和档案发生冲突时，以当前代码及可重复验证结果为准，并修正文档。
- 不建立临时文档目录；未定稿方案直接在对应 history 档案中标记为 `planned`。
